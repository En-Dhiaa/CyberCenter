### ADR-001: نمط المعمارية - Modular Monolith بدلاً من Microservices
- **السياق:** تتطلب مراكز الألعاب والإنترنت معالجة سريعة للغاية للأوامر والمدفوعات ضمن شبكة محلية LAN موحدة، مع ترابط وثيق بين إدارة الأجهزة والجلسات والمبيعات والمالية.
- **القرار:** بناء النظام كـ **Modular Monolith** موحد مقسم بوضوح إلى وحدات ومشاريع مستقلة تتبع مبادئ المعمارية النظيفة (Clean Architecture)، بدلاً من توزيع النظام إلى خدمات صغيرة متعددة (Microservices).
- **المبررات:**
  - القضاء على تعقيد اتصالات الشبكة الموزعة (Network Latency) بين الخدمات المصغرة في الشبكة المحلية.
  - ضمان تنفيذ المعاملات المالية الحساسة بأعلى درجات التماسك (ACID Transactions) دون الحاجة لبروتوكولات Saga المعقدة.
  - انخفاض تكلفة التشغيل والصيانة لمالك المركز بنسبة تزيد عن 70%، مع إمكانية فصل أي موديول مستقبلاً عند الحاجة.

### ADR-002: خادم الويب - ASP.NET Core 8 LTS و C#
- **السياق:** الحاجة إلى خادم عالي الأداء ومنخفض استهلاك الذاكرة، قادر على إدارة مئات اتصالات الـ WebSockets المتزامنة بكفاءة ودون تأخير، مع دعم قوي للتشغيل على ويندوز ولينكس.
- **القرار:** استخدام **ASP.NET Core 8 LTS** مع C# كمحرك أساسي للـ Backend.
- **المبررات:**
  - تفوق ASP.NET Core المثبت عالمياً في اختبارات الأداء (TechEmpower Benchmarks) في معالجة طلبات I/O غير المتزامنة.
  - الدعم المدمج الكامل لـ SignalR و Background Hosted Services دون الحاجة لمكونات إضافية خارجية.
  - استقرار نسخة الـ LTS (دعم طويل الأمد) وتوافر منظومة حماية مؤسسية متقدمة.

### ADR-003: قاعدة البيانات - PostgreSQL 15+ مع EF Core
- **السياق:** الحاجة لقاعدة بيانات علائقية مفتوحة المصدر وقوية جداً تدعم المعاملات المعقدة، المؤشرات المتقدمة، حقول الـ JSONB لتخزين مواصفات الأجهزة وسجلات التغيير، والامتدادات التشفيرية.
- **القرار:** اعتماد **PostgreSQL** محركاً رئيسياً لقاعدة البيانات مع **Entity Framework Core**.
- **المبررات:**
  - كفاءة PostgreSQL العالية في معالجة القراءة والكتابة المتزامنة ودعمها الممتاز لأنواع بيانات `UUID` و `TIMESTAMPTZ` و `JSONB`.
  - عدم وجود تكاليف تراخيص تجارية مرهقة على صاحب المركز (مقارنة بـ SQL Server أو Oracle).
  - سهولة النسخ الاحتياطي عبر أدوات `pg_dump` وسهولة النشر عبر Docker أو مباشرة على نظام التشغيل.

### ADR-004: الاتصال اللحظي - SignalR مع Fallback إلى REST
- **السياق:** تتطلب شاشات التحكم الحية وشاشات المطبخ وأجهزة العملاء استجابة فورية للأوامر (قفل الجهاز، تمديد الوقت، طلب وجبة جديدة) في أجزاء من الثانية.
- **القرار:** استخدام **SignalR WebSockets** كقناة اتصال رئيسية ثنائية الاتجاه، مع توفير مسارات REST API بديلة في حال عدم استقرار اتصال الـ WebSocket.
- **المبررات:**
  - إدارة الاتصال التلقائي وإعادة المحاولة (Automatic Reconnection) المدمجة في SignalR.
  - انخفاض حمل الباندويث بنسبة تتجاوز 85% مقارنة بالاستعلام الدوري المتكرر (HTTP Polling).

### ADR-005: لوحة الإدارة - React و TypeScript و Vite و Tailwind CSS
- **السياق:** توفير لوحة إدارية فائقة السرعة، متجاوبة، تدعم اللغتين العربية (RTL) والإنجليزية (LTR)، مع هوية بصرية مذهلة تلائم صالات الألعاب.
- **القرار:** استخدام **React 18** مع **TypeScript** و **Vite** لتوليد التطبيق، مع **Tailwind CSS** للتصميم و **TanStack Query** لإدارة الكاش وتزامن بيانات الخادم.
- **المبررات:**
  - سرعة بناء وتشغيل فائقة مع Vite مقارنة بـ Webpack و Create React App القديمة.
  - أمان الأنواع البرمجية (Type Safety) عبر TypeScript مما يمنع أخطاء الـ Runtime الشائعة.
  - مرونة Tailwind CSS في بناء سمة Dark Premium فخمة وتطبيق قلب الاتجاهات RTL/LTR بسهولة عبر Logical Properties.

### ADR-006: بنية العميل - فصل خدمة النظام (Agent) عن واجهة الألعاب (Shell)
- **السياق:** إذا تم تشغيل واجهة المستخدم بصلاحيات مدير النظام، يسهل على المهاجم أو الزائر استغلالها لفتح نافذة ملفات بصلاحيات النظام واختراق المحطة. وإذا تم تشغيلها بصلاحيات عادية، لن تستطيع حماية ملفات النظام وتنفيذ أوامر الإدارة.
- **القرار:** فصل العميل إلى مكونين:
  1. `CyberCenter.Agent`: خدمة نظام خلفية بدون واجهة تعمل بصلاحيات `LocalSystem`.
  2. `CyberCenter.Shell` و `CyberCenter.HUD`: واجهات مستخدم تعمل تحت حساب الزائر المحدود (Standard User)، وتتواصل مع الـ Agent عبر IPC محلي مشفر.
- **المبررات:**
  - تطبيق مبدأ فصل الصلاحيات ومنع ثغرات تصعيد الصلاحيات (Privilege Escalation).
  - قدرة خدمة الـ Agent على مراقبة واجهة الـ Shell وإعادة تشغيلها فوراً إذا حاول الزائر إغلاقها.

### ADR-007: أمان الألعاب - حظر حقن الأكواد واعتماد Borderless HUD
- **السياق:** تستخدم بعض برامج المقاهي القديمة DLL Injection لحقن نصوص الوقت داخل نوافذ الألعاب، مما يؤدي فوراً لحظر حسابات اللاعبين نهائياً في ألعاب مثل Valorant (Riot Vanguard) و CS2 (VAC) و Fortnite (Easy Anti-Cheat).
- **القرار:** حظر تام لأي تقنية حقن ذاكرة أو DLL Hooking. يتم برمجة الـ HUD كنافذة شفافة مستقلة ذات أولوية عليا (Transparent Click-Through Topmost Window).
- **المبررات:**
  - حماية كاملة لحسابات اللاعبين وممتلكاتهم داخل الألعاب وضمان عدم صدور أي حظر غش.
  - ثبات النظام وعدم التسبب في انهيار الألعاب أو ظهور الشاشات الزرقاء (BSOD).

### ADR-008: ضبط الوقت - سلطة الخادم وعقود الإيجار المشفرة (Session Leases)
- **السياق:** في الأجهزة العميلة، يستطيع المستخدم العبث بساعة ويندوز أو إيقاف خدمات ضبط الوقت لمحاولة تمديد جلسة اللعب مجاناً.
- **القرار:** الخادم المركزي هو المرجع الوحيد للوقت. يمنح الخادم للعميل عقداً زمنياً موقعاً رقمياً (Session Lease Token) بمدة محدودة يتم تجديده في كل نبض (Heartbeat).
- **المبررات:**
  - استحالة سرقة الوقت؛ تغيير ساعة ويندوز على جهاز العميل لن يؤثر على انتهاء العقد الموقع رقمياً.
  - الصمود التلقائي أمام انقطاع الشبكة المؤقت مع الإغلاق الآمن بعد انتهاء فترة السماح.

### ADR-009: تشفير كروت الـ PIN وإخفائها
- **السياق:** الكروت المؤقتة تستخدم رموز PIN مكونة من 16 رقماً. يجب حمايتها من التسريب من قبل الموظفين أو قواعد البيانات.
- **القرار:** توليد رموز PIN عشوائية وتشفيرها بواسطة خوارزمية Hash آمنة فور إنشائها، وتخزين كود مشوش فقط في الجداول العامة (`CC-****-****-1234`). لا يُعرض الـ PIN بالكامل إلا أثناء الطباعة أو التصدير اللحظي فقط.
- **المبررات:**
  - منع الموظفين من تصوير أو نسخ رموز الكروت واستخدامها مجاناً.
  - الامتثال للمعايير الأمنية المعتمدة لحماية البيانات الحساسة.

### ADR-010: محاسبة الطاقة - التمييز بين القياس الفعلي والتقدير الحسابي
- **السياق:** لا يمكن اعتبار ساعات تشغيل الحاسوب دليلاً قطعياً على استهلاك الكهرباء لأن استهلاك الجهاز يختلف جذرياً بين الخمول (60W) وضغط الألعاب الثقيلة (450W+).
- **القرار:** توفير واجهتين متوازيتين في نظام الطاقة:
  1. الاستهلاك المقاس بالعداد الذكي (Measured kWh عبر Smart Energy Meter أو الإدخال اليدوي الموثق لقراءة العداد).
  2. الاستهلاك الحسابي التقديري المعتمد على معدلات الاستهلاك المتوسطة للمحطات.
- **المبررات:**
  - الدقة والأمانة المحاسبية وعدم تضليل الإدارة بأرقام تقديرية باعتبارها فواتير فعلية.

### ADR-011: المالية ودفتر الأستاذ - منع الحذف المباشر للقيود المعتمدة
- **السياق:** تسرب الإيرادات في مراكز الألعاب يحدث غالباً عبر قيام الموظفين بحذف عمليات بيع أو جلسات سابقة بعد تحصيل أموالها نقداً.
- **القرار:** حظر عمليات الحذف والتعديل المباشر (No Direct UPDATE / DELETE) على جداول القيود المالية بعد اعتمادها وإقفال الفترات. أي تعديل يجب أن يتم عبر قيد تسوية عكسي (Reversal Entry) مسجل وموثق بالموظف والسبب في سجل التدقيق.
- **المبررات:**
  - القضاء على ثغرات التلاعب والسرقة النقدية.
  - مطابقة معايير المحاسبة الدولية في تدقيق السجلات المالية (Audit Trail & Double-Entry Principles).
